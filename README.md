# 慢慢长大 · 育儿内容路由

## 速览

- GitHub Pages 托管公开网页，GitHub Actions 定时采集和发布，无需 Cloudflare 账号或数据库；配置 YouTube API Key 后使用官方接口，未配置时使用 RSS。
- 每天北京时间06:17计划更新，主分支推送和维护者手动运行也会触发；排程可能延迟，以页面显示的采集时间为准。
- 只做内容发现、八主题筛选和原片跳转，不保存实践记录、收藏或用户账号。
- 配置Key后按具体玩法主题搜索，不局限订阅频道；没有Key时使用八个频道的免费RSS。不需要授权你的YouTube账号，另有人工精选阅读入口。
- DeepSeek V4.1 Flash在后台生成中文速览；可选接入Supadata原生字幕，提炼带原片时间点的玩法笔记。未配置字幕密钥时仍依据标题与简介。网页访问不调用模型，没有微信或邮件通知。

## 内容范围

关注12—24个月的语言互动、大运动、精细动作、感官盆、美育、绘本、亲子游戏与陪伴方式。

`config.json` 配置八个英文主题查询：感官玩法、精细动作、室内大运动、美育、亲子游戏、轮流交流、互动绘本与跟随孩子的陪伴示范。按北京时间每天轮转四个方向，两天覆盖全部八个；每次两个近期查询、两个热门查询，同一方向下次出现时交换排序。近期查询限采集前90天，热门查询不限作者发布日期，保留好用的经典。来源日期逐条原样展示；经典可能重复，不保证每天每条都是新片，也不承诺每个方向每天有内容。

每个查询最多10条ID，再统一读取最多40个ID的公开视频资料、时长、播放量与点赞量。先筛内容，再按具体玩法标题和明确1—2岁语境排序，同档参考播放量、点赞量与作者日期。没有最低热度门槛；缺失计数不写成0，热度不代表质量或安全。最后最多20条、每作者最多2条、最多10位作者，不拿离题内容补位。作者面板列本批实际发现的作者，不代表逐一核验过其全部作品。无API Key时的八个RSS来源保留14天窗口：Raising Little Talkers、Pathways、Emma Hubbard、The Artful Parent、MOTHERCOULD、Lovevery、ZERO TO THREE与Dr. Lauren Baker；品牌与机构内容仍逐条筛选。

`content.mjs` 从标题和简介首段排除明显临床课程、自闭症训练与讲座/播客，从标题排除明显促销与被动动画合辑，再按标题和简介推导主题；错误年龄检查使用有界简介。出现明确其他年龄时，需要另有明确1—2岁或12—24个月证据才保留，泛称toddler不能覆盖错误年龄。普通治疗师提供的亲子游戏不会仅因职业而排除；玩法组合中的“x”也不单独作为广告依据。检索词只能提供主题线索，文字没有足够主题时会标“主题按检索词推断”，不作为确认月龄的依据。规则会误选或漏选，元数据不能证明实际画面内容。

模型优先概括可借鉴的互动与玩法，通常40—100字，最多两点，不凑课堂观点。没有字幕时只读标题与公开简介前800字符；有字幕时显示实际语言、完整轨或已读时间范围，玩法笔记仅保留可核对的原片时间点。信息不足留空，不假称看过画面或完成安全审阅。AI低相关候选默认隐藏，原始数据仍保留；未分析的内容如实显示原文。页面计数与概要覆盖率以可见候选为分母，隐藏数量只指AI低相关条目，不等于所有规则排除数。

首页另放Busy Toddler的1岁活动目录、Hands On As We Grow的清水画画文章（作者标20个月）和Hazie的家务互动视频（作者示范13个月）。这是手动常备参考，不计入每日新增，也不保证每项材料都适合每个孩子。更多阅读入口仍可手动打开；X目前未自动采集。本站公开免登录，原片由YouTube控制，部分观看可能要求登录，缺少年龄限制标记也不保证匿名可看。缩略图由验证过的视频ID构造，浏览器会连接YouTube图片服务 `i.ytimg.com`；不发送本站Referrer，图片失败时继续显示文字，没有嵌入播放器。

## 本地运行

需要Node.js 22以上（推荐24）；AI后台传输使用Python 3.9以上标准库，无额外Python依赖。在本目录执行：

```sh
npm ci --ignore-scripts
npm run collect
npm run captions
npm run enrich
npm run dev
```

打开 [本机预览](http://127.0.0.1:8787/)。`collect` 先生成真实订阅；`captions`在未提供字幕密钥时不请求服务。未提供AI环境变量时，`enrich`复用有效缓存、其余保留原文并注明未启用，不调用模型。两个后台命令均支持`--cache-only`，只复用缓存。`dev`构建并在本机提供静态网页，按Ctrl+C停止。没有采集成功时不会用示例数据凑数。

```sh
npm run check
```

检查覆盖订阅校验、来源公平选取/部分失败、字幕毫秒换算/头中尾选段/时间点证据、结构化速览、坏响应与超时、缓存失效、中文筛选、公开字段白名单和实际构建子路径。测试只使用合成资料；真实采集、模型调用和公网发布分别核验。

## GitHub Pages 发布

本项目使用公开仓库的免费Pages与标准GitHub Actions，无需购买域名。源码和提交历史公开，采集数据与缓存不提交Git历史。官方YouTube接口、模型和可选字幕服务各用一个Actions Secret；无YouTube Key时的RSS无需密钥。

1. 仓库 Settings → Pages → Build and deployment，Source 选 **GitHub Actions**。
2. 推送`main`会自动采集、复用已恢复的字幕和概要缓存并发布，未命中项保留原文；push只读取YouTube采集Key，不读取字幕/模型密钥或产生新字幕/模型调用。
3. 正常日更由schedule生成新概要。也可由仓库维护者到Actions → **Publish parenting feed** → **Run workflow**，选择`main`，授权手动补跑/验证；浏览器刷新只读取已发布列表。
4. 发布成功后，从`deploy`任务或Pages设置页打开真实网址。网页和数据使用相对路径，适配`/<仓库名>/`项目地址。

工作流使用 UTC `17 22 * * *`，即北京时间次日06:17。网页“刷新内容”只重新读取已发布列表，不会触发一次新采集。

页面分别显示本站更新时间（本批静态页面生成时刻，GitHub部署完成后才对外生效）、本批采集时间和每条作者原始发布时间，有概要时显示概要生成时间，统一使用北京时间并精确到秒。命中缓存的概要保留原生成时间，不会用本站更新时刻覆盖作者日期或概要日期。

主题发现至少一个查询成功且有合适候选即可发布，并显示近期/热门各自成功数与查询不完整提示；任一查询失败且最终无候选时中止发布、保留上次网站。仅四个查询全部成功且无合适候选时发布零条。频道RSS模式至少一个来源成功即可发布，失败源本批不带旧条目。所有查询或来源失败均保留上次页面及采集时间，不能把保留页面当本次成功；页面拒绝展示超过28天的旧列表，旧部署公开元数据在下一次成功部署前仍可能存在。

采集日志用`collection_source`标明`youtube_api`或`rss`；失败诊断只记录HTTP状态码或固定错误类型，不输出请求URL、头、正文、密钥或原始错误信息。RSS重试与截止时间不变，API预算见下节。

主题发现每批最多20条（RSS最多40条），元数据每5条一个模型请求，字幕分析每条单独请求且最多3次；原模型上限仍为8次，每次最多4096输出token、45秒截止，整个概要阶段365秒，不自动重试。20条全部未缓存且3条字幕分析成功时，模型最多调用3+ceil(17/5)=7次；另有最多3次原生字幕获取，属于不同服务。RSS40条在同样模型上限下最多覆盖3+5×5=28条，其余如实显示原文；不保证每次全部覆盖。首个模型故障后停止余下请求，保留已成功的新概要/缓存；字幕升级失败时仍保留有效的元数据概要，升级成功后仅缓存字幕概要。模型故障不阻断频道内容发布。首次或缓存淘汰后可能重新调用，用量以TokenHub套餐统计为准，不承诺全平台最低价或固定月费。

概要按模型、提示版本与原始标题/简介/日期等指纹复用；字幕概要另包含实际语言、范围和片段内容，本轮更新了玩法筛选提示版本，旧宽泛相关性概要不会自动复用；播放/点赞计数不进入模型输入与指纹，不因热度变化重复调用。Actions缓存只保留本批候选、可能淘汰；两个缓存文件分别限制为1MiB。静态产物仍只有五个文件，不含调用器、配置、缓存、环境、依赖或审稿资料。

GitHub定时任务可能延迟。公开仓库60天无repository activity时会自动停用schedule；官方未完整列举活动范围，也未要求必须人为操作，不能保证采集/发布产物会重置计时。停用后到Actions → **Publish parenting feed** → **Enable workflow**重新启用。不添加无内容保活提交。依据：[排程说明](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows)、[自动停用规则](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)、[Pages 免费条件](https://docs.github.com/en/pages/getting-started-with-github-pages)。

## YouTube官方API配置

在Google Cloud项目启用YouTube Data API v3，由所有者创建仅限该API、未绑定服务账号的Key，保存为仓库Actions Secret `YOUTUBE_API_KEY`。Key只进主分支push/schedule/手动的采集步骤和固定Google端点请求头，不进URL、日志或网页。应用限制为“无”适用于动态runner；泄露后其他来源仍可消耗配额，仓库写权限成员也可修改工作流使用它。未配置时使用RSS；有Key但API失败时不静默回退RSS或旧条目。

主路径固定请求Google官方 `search.list`，每轮4次、两个 `order=date` 与两个 `order=viewCount`；设置 `type=video`、`safeSearch=strict`、`relevanceLanguage=en`，附加 `-autism -podcast -webinar -lecture -cartoon`。这些只是搜索倾向，不保证作者国别、语言或安全。搜索仅取视频ID，再用一次 `videos.list` 读取规范元数据和计数；不翻页、不请求任意上游链接。作者时间取 `snippet.publishedAt`。非公开、直播/预告、年龄限制、超过20分钟、未来超过5分钟的条目跳过；90天以前的视频只有由热门查询发现时保留。查询格式异常视该查询失败，规范资料异常整批失败，保留旧部署；规范返回缺失的ID可跳过。每个响应最多256KiB，过大时失败，不扩大预算或拆批追加请求。

正常4次搜索+1次规范资料请求；每资源最多重试一次，最坏8次搜索+2次资料请求。当前官方配额说明搜索独立100 calls/day、每次在Search Queries配额桶中计1单位，其他配额另计；实际以项目控制台为准，不沿用旧100单位/搜索的口径。项目只读观察标签：Search Queries per day=100；Queries per day=10,000；Video Batch Get Stats Queries per day=10,000。该预算是单轮上限，不是项目日/月硬封顶；push、手动和其他消费者共享额度，耗尽则保留上次网站，不新增保活提交或每日计数存储。

每尝试最多6秒，搜索与规范资料各13秒、总26秒（RSS保持15秒）。API26+字幕75+概要365=466秒，安装、缓存和上传另占时间，仍受10分钟构建截止限制。参见[官方搜索参数](https://developers.google.com/youtube/data/reference/rest/v3/search/list)、[视频资料](https://developers.google.com/youtube/data/reference/rest/v3/videos/list)、[当前配额口径](https://developers.google.com/youtube/data/determine_quota_cost)和[Key请求头](https://docs.cloud.google.com/apis/docs/system-parameters)。

## TokenHub后台配置

在仓库Settings → Secrets and variables → Actions添加Repository Secret：

- `TOKENHUB_API_KEY`：获授权使用的TokenHub个人套餐Key。

模型请求固定为`deepseek/deepseek-flash`（官方当前映射为DeepSeek V4.1 Flash 1017），关闭思考、使用JSON输出。后端固定请求`https://tokenhub.tencentmaas.com/plan/v3/chat/completions`，不读取环境中的端点覆盖值，也不回退到按量计费接口。Key仅进入后台进程环境与Authorization头，不放网页、仓库、URL参数、文件或日志。只有`main`的schedule/手动补跑步骤读取Secret；PR只测试，push只用缓存。不要在聊天中发送Key。

Token Plan个人版官方规则限制自动化脚本、自定义应用后端和非交互式批量调用；本项目按所有者明确选择使用个人套餐接口，不代表服务商批准此用途。若服务拒绝、额度耗尽或暂停，保留原文更新，不伪装客户端、绕过限制或改用其他计费产品。参见[个人版订阅须知](https://cloud.tencent.com/document/product/1823/130060)、[个人版接入配置](https://cloud.tencent.com/document/product/1823/130119)和[模型版本公告](https://cloud.tencent.com/announce/detail/2516)。

仓库有写权限的人可修改工作流并使用该Secret，因此只向可信协作者开放写权限。GitHub托管runner上的实际接通需单独验证；不可达时保留原文更新，不把Key移到浏览器。旧AIHub Secrets不再被本工作流引用。

## 可选字幕配置

需要所有者自行选择并注册[Supadata免费账号](https://dash.supadata.ai/)，确认该服务的条款，再将API Key保存为仓库Actions Secret **`SUPADATA_API_KEY`**。不要发到聊天或写入代码。未配置时不请求服务；正常排程/手动补跑的未命中项显示“字幕尚未接通”，push只用缓存，未命中项显示“本次未读取字幕”。准备代码不代表已注册或验证真实字幕。

服务[当前免费额度](https://supadata.ai/pricing)为每月100 credits，已有字幕每次1 credit。后台固定请求公开`https://api.supadata.ai/v1/transcript`，只发送由视频ID构造的YouTube链接，使用`mode=native`、`text=false`、`lang=en`（优先语言，页面以实际返回语言为准）和`chunkSize=500`；Key仅在`x-api-key`头里。不使用生成转录、自动模式、翻译或付费加购，不读取YouTube登录、Cookie、音视频或代理配置。YouTube官方字幕下载需要视频编辑权限，普通观看账号不能解决任意公开视频的字幕授权问题。

每次正常排程/手动补跑最多3次字幕获取，与首页共用具体玩法/明确年龄优先、同档参考热度与日期的排序，不因简介更长而优先；缓存命中不消耗请求。不代表每月硬封顶：手动多跑也占额度，不保证每次成功均有可用字幕。遇鉴权、额度、网络或响应格式故障立即停止本轮后续获取；暂无字幕或待处理缓存24小时，不轮询后台任务。单请求23秒、整个字幕阶段75秒；服务失败继续使用已有概要或标题与简介。排程、依赖和缓存耗时还受GitHub平台影响，构建任务总截止10分钟。

字幕先校验时间戳（服务毫秒转为秒），限制4小时、每条1000字符；小轨全部读入，长轨取头/中/尾，最多300条、序列化UTF-8不超过12KiB。实际完整模型请求仍限制24KiB，必要时缩小片段，放不下则退回元数据。页面显示实际已读区间；片段没有说明不能推断整段原片也没说明。

玩法笔记只保留字幕有连续原文证据的月龄、最多3条材料、4条按原序的步骤和3条注意事项，时间点由已读字幕生成，模型不能自填链接；原文引用仅用于后台匹配，不公开。证据不匹配时舍弃该份玩法笔记，仍可保留有效的普通字幕概要。未明确月龄不把“toddler”换算为12—24个月；低相关、其他年龄、诊疗或商品内容不改写成适龄玩法。字幕可能有识别错误，原文匹配也不能证明中文释义或做法正确，不等于已看过画面。

有效字幕快照最多复用28天，不因超过7天而把仍在候选中的字幕卡降级。主题发现可含旧经典，RSS仍只选最近14天发布的条目；28天是旧部署/快照的最长有效期，不是保留旧候选的承诺。字幕片段只存后台`data/captions-cache.json`与Actions缓存，不进Git历史或Pages；公开仓库的Actions缓存不是机密存储，分支/PR读者可能访问基础分支缓存，不得存入秘密或个人内容。PR工作流本身不恢复缓存或读取Secrets。字幕作者权利仍归创作者，服务可返回文本不等于授予任意转载权。

## 维护

编辑`config.json`的八个唯一主题查询（每个最多160字符、不含控制字符）或`content.mjs`规则，再推送`main`。RSS当前8个频道，上限10个，真实频道ID与身份须先核实。日更时间、RSS14天窗口、28天页面过期与八个主题保持既有设置；不新增账号、依赖、数据库或工作流。

未配置YouTube Key时，RSS使用 `https://www.youtube.com/feeds/videos.xml?channel_id=…`，其上游可能暂时返回404/500；可选字幕独立按上节配置。`data/`、`dist/`、旧本机运行数据与审稿目录均不提交。此前浏览器记录不会被读取或上传。

Cloudflare Worker、D1配置与开发依赖已移除。共享的`feed.mjs`仅包含浏览器数据校验和筛选；后台采集、AI调用与构建代码位于`scripts/`，不进入网站产物。
